# SlidFix — пересечения стыков досок и лаг

> IMPORTANT:
> These values are UX/demo assumptions only.
> They are not validated SlidFix engineering installation rules.

**SlidFix работает между соседними досками и устанавливается на лагу, в месте
пересечения лаги со стыком. Крепления не размещаются между лагами.**

Расчёт остаётся демонстрационным. Правильный принцип привязки не означает,
что текущие шаги, отступы и схемы являются утверждённым монтажным регламентом.

## 1. Доски и стыки

Порядок построения: ориентация → доски → внутренние стыки → поперечные лаги →
пересечения → исключение проёмов → выбор схемы.

```text
extentMm = vertical ? wallWidth × 1000 : wallHeight × 1000
boardCount = ceil(extentMm / boardWidthMm)
jointCount = max(0, boardCount − 1)
jointPositions[i] = (i + 1) × boardWidthMm / 1000
```

Последняя доска обрезается по границе стены. Внешний край стены не является
стыком двух досок. При точном делении дополнительная доска/стык не создаётся.

Для вертикальных досок `jointPositions` — X-координаты вертикальных стыков.
Для горизонтальных — Y-координаты горизонтальных стыков. Доски и стыки считаются
по полной стене до вырезания проёмов; это не закупочная ведомость с раскроем.

Ширина доски прямо влияет на число стыков и потенциальных креплений.
Толщина хранится отдельно в `boardThicknessMm`, по умолчанию 20 мм.

```text
Board thickness is currently stored as a project parameter but does not change quantity until validated SlidFix engineering rules are supplied.
```

Поля толщины в интерфейсе нет; фиксированное значение 20 мм сохранено в JSON
для совместимости. Оно не является подтверждением совместимости изделия.
Толщина не меняет количество и не используется для выдуманного выбора шурупов.

## 2. Поперечные лаги

| Ориентация досок | Стыки | Лаги | Направление повторения лаг |
| --- | --- | --- | --- |
| Вертикальная | Вертикальные | Горизонтальные | По высоте стены |
| Горизонтальная | Горизонтальные | Вертикальные | По ширине стены |

Первая ось лаги находится в `edgeClearanceMm` от края в направлении повторения.
Далее оси строятся с шагом `lagSpacingMm`, пока не входят в такой же отступ у
противоположного края. Дополнительная крайняя ось не добавляется: расстояние
между всеми соседними осями равно выбранному шагу. Остаток у края стены
не создаёт короткий последний промежуток.

Например, при высоте 2,8 м и горизонтальных лагах с шагом 600 мм оси имеют
Y = 0,18; 0,78; 1,38; 1,98; 2,58 м. При вертикальных лагах на стене шириной
6 м — 10 осей от 0,18 до 5,58 м. Ось 5,82 м не добавляется, поскольку
до предыдущей осталось бы только 240 мм вместо выбранных 600 мм.

Отступ 180 мм в этой модели задаёт положения крайних осей по направлению
повторения лаг. Он не удаляет целиком крайние внутренние стыки досок в другом
направлении. Дополнительные инженерные отступы для креплений пока не задаются.

Лага показана полупрозрачной полосой **50 мм** и пунктирной осью.
Реальная координата установки в demo-модели совпадает с осью лаги.
Полосы и стыки визуально вырезаются только внутри проёмов через SVG-маску.
Перемычки и дополнительные элементы обрамления не рассчитываются.

## 3. Пересечения

Для каждой пары `jointIndex × lagIndex` создаётся кандидат:

```text
Вертикальные доски / горизонтальные лаги:
  x = jointPositions[jointIndex]
  y = lagPositions[lagIndex]

Горизонтальные доски / вертикальные лаги:
  x = lagPositions[lagIndex]
  y = jointPositions[jointIndex]
```

Координаты берутся непосредственно из массивов осей и стыков. Никаких
середин пролётов, смещений с оси или независимых рядов креплений больше нет.
Каждая точка содержит `x`, `y`, `jointIndex`, `lagIndex`.

## 4. Проёмы

Каждый кандидат проверяется отдельно. Окно или дверь расширяются на
`openingClearanceMm` со всех сторон. Если точка находится внутри этой области
или касается её границы, она исключается. Весь стык или вся лага не удаляются:
их другие пересечения остаются доступными.

Одиночное окно и центральная дверь центрируются по ширине. Левая дверь
начинается на `openingSideInsetMm` от левого края. Двери всегда имеют Y = 0;
окна — Y = `sillHeightMm / 1000`.

Для двух окон:

```text
left = (wallWidth − 2 × openingWidth − mullionWidthMm / 1000) / 2
window1.x = left
window2.x = left + openingWidth + mullionWidthMm / 1000
```

Сохраняются симметрия, подоконная зона и центральный простенок.

```text
2 × openingWidth_mm + mullionWidthMm <= wallWidth_mm − 2 × openingSideInsetMm
sillHeightMm + openingHeight_mm <= wallHeight_mm − openingTopInsetMm
```

При увеличении простенка может уменьшиться ширина окон; при увеличении ширины
окон — простенок. При увеличении высоты окна может уменьшиться подоконная зона,
и наоборот. Связанные значения ограничиваются и показываются в полях;
сообщение объясняет корректировки. Неоконченный/невалидный ввод не ломает
предыдущий расчёт и нормализуется при уходе из поля.

## 5. Стандартная и шахматная схемы

**Стандартная:** все допустимые пересечения после исключения проёмов.

**Шахматная:** среди доступных пересечений выбираются пары с
`(jointIndex + lagIndex) % 2 === 0`. Первый стык использует лаги 1, 3, 5…,
соседний — 2, 4, 6… (номера здесь пользовательские, от единицы).
Индексы не перенумеровываются после вырезания проёмов.

**Сохранение крепления на каждом доступном стыке:** если проём закрыл все
пересечения выбранной чётности, но на стыке есть другие допустимые пересечения,
сохраняется одно из них с наименьшим `lagIndex`. Такая точка имеет
`coverageFallback: true`. Она по-прежнему находится строго на лаге и вне
зоны проёма. Интерфейс сообщает число таких стыков.

Это локальное исключение из чередования, необходимое, чтобы шахматная схема
не оставляла доступный стык совсем без креплений. Если недоступны все
пересечения стыка, крепления на нём не выдумываются.

Шахматная схема — подмножество стандартной. Обычно креплений меньше; при
крайне ограниченной геометрии количества могут совпасть. Процент экономии и
инженерная допустимость не заявляются.

## 6. Итоги

```text
boardCount = количество досок по полной стене
jointCount = boardCount − 1
lagCount = lagPositions.length
mountPointCount = число всех допустимых пересечений после исключения проёмов
unitCount = points.length после применения выбранной схемы
packs = ceil(unitCount / 10)
screws = unitCount × 2
grossArea = wallWidth × wallHeight
netArea = grossArea − sum(opening.w × opening.h)
```

«Количество точек монтажа» показывает доступный максимум полной схемы.
«Крепления SlidFix» — количество в выбранной схеме. В стандартном режиме
показатели совпадают, в шахматном обычно различаются.

## 8. Экспорт версии 3

Координаты — метры от левого нижнего угла стены (`coordinateUnit: "m"`).
Параметры `*Mm` заданы в миллиметрах. `jointPositions` и `lagPositions` —
массивы координат в метрах; их оси указаны в `jointAxis` / `lagAxis`.
Индексы в `points` начинаются с нуля.

JSON включает параметры досок и толщину, число досок/стыков, направления и
координаты стыков/лаг, ширину лаги, проёмы, точки и итоги. Неиспользуемые
верхнеуровневые `sillHeightMm` / `mullionWidthMm` равны `null`; сохранённое
состояние формы хранит последние значения для переключения пресетов.
Версия 3 заменяет прежние пролёты и `verticalFastenerPitchMm`.

SVG включает доски, стыки, полосы лаг, пунктирные оси, проёмы, маркеры,
размеры и русское предупреждение. Временная подсветка снимается при экспорте.
Геометрия самого SlidFix, фотографии и ссылки на изображения изделия
не включаются ни в SVG, ни в JSON.

Начальное превью: горизонтальные доски, стена 6 × 2,8 м, окно 1,8 × 1,2 м
по центру обеих осей (подоконная зона 800 мм). Поле подоконной зоны остаётся
доступным для ручной настройки.
