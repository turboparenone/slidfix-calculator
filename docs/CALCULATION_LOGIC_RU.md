# SlidFix — демонстрационная модель каркаса и расстановки

> IMPORTANT:
> These values are UX/demo assumptions only.
> They are not validated SlidFix engineering installation rules.

Предварительный расчёт. Текущие параметры шага и расстановки используются для
демонстрации работы калькулятора и будут уточнены после утверждения инженерного
регламента SlidFix.

## Единицы и координаты

Размеры стены и проёмов заданы в метрах; шаг лаг, шаг рядов, подоконная высота
и простенок — в миллиметрах, что отражено в именах параметров `*Mm`.
Координаты в `lagPositions`, `spans`, `rowPositions`, `openings` и `points`
экспортируются в метрах (`coordinateUnit: "m"`). Начало координат — левый
нижний угол стены. Индексы пролётов и рядов начинаются с нуля.

## 1. Вертикальные оси лаг

Первая ось расположена на расстоянии `edgeClearanceMm` от левого края.
Последующие оси идут с шагом `lagSpacingMm`. Последняя ось добавляется на
расстоянии `edgeClearanceMm` от правого края, если её ещё нет. При точном
совпадении повторная ось не создаётся.

Последний пролёт может быть короче заданного шага. Ни один пролёт не шире шага,
и ни одна ось не выходит за стену. Это геометрическая демонстрация, а не
утверждённое правило крайних стоек.

Визуальные линии лаг прерываются внутри проёмов. Перемычки и дополнительные
обрамляющие стойки не моделируются. Количество лаг — число исходных осей,
а не число отрезков после вырезания окон и не закупочная ведомость каркаса.

## 2. Пролёты

Каждая пара соседних осей образует пролёт:

```text
span.left = lagPositions[i]
span.right = lagPositions[i + 1]
span.center = (span.left + span.right) / 2
```

Крепления всегда имеют X-координату `span.center`. Свободная сетка и смещение
точек на половину шага больше не применяются.

## 3. Ряды креплений

```text
rowY_mm = edgeClearanceMm + rowIndex × verticalFastenerPitchMm
rowY_mm <= wallHeight_mm − edgeClearanceMm
```

Последний ряд не добавляется принудительно у потолка. Число рядов меняется
дискретно: изменение шага не обязано менять количество при каждом движении
поля, но всегда меняет координаты соответствующих рядов.

## 4. Схемы

**Стандартная:** каждый ряд использует все допустимые пролёты.

**Шахматная:** ряд с индексом 0 использует пролёты 0, 2, 4…; ряд 1 — 1, 3, 5…;
далее чередование повторяется. После исключения проёмов индексы не пересчитываются.
Так рисунок не смещается из-за окон и дверей.

Это демонстрационный экономичный режим. Процент экономии не обещается:
результат зависит от числа пролётов, рядов и проёмов. Шахматная схема является
подмножеством стандартной; её применимость требует инженерного подтверждения.

## 5. Проёмы и технологическая зона

При проверке строки проём расширяется на `openingClearanceMm` со всех сторон.
Если **весь интервал пролёта на высоте ряда** пересекает эту область,
крепление исключается. Проверки только середины пролёта недостаточно.
Касание границы расширенного проёма также считается пересечением.

Глухая стена не имеет проёмов. Одиночное окно и центральная дверь выравниваются
по центру стены. Левая дверь отстоит от края на `openingSideInsetMm`.
Нижняя координата любой двери равна 0. Окна начинаются на высоте `sillHeightMm`.

Для двух окон:

```text
left = (wallWidth − 2 × openingWidth − mullionWidthMm / 1000) / 2
window1.x = left
window2.x = left + openingWidth + mullionWidthMm / 1000
```

Пара окон симметрична. Ограничения учитывают боковые отступы:

```text
2 × openingWidth_mm + mullionWidthMm <= wallWidth_mm − 2 × openingSideInsetMm
sillHeightMm + openingHeight_mm <= wallHeight_mm − openingTopInsetMm
```

При изменении простенка преимущество получает новый простенок: при необходимости
уменьшается ширина окон. При изменении ширины окна ограничивается простенок.
При изменении высоты окна может уменьшиться подоконная зона; при изменении
подоконной зоны — высота окна. Изменение стены пересчитывает связанные размеры.
Поля показывают действительные значения, а интерфейс сообщает о корректировках.
Неполный или некорректный ввод сохраняет последний расчёт до ухода из поля;
после ухода значение ограничивается допустимым диапазоном.

## 6. Ориентация облицовки

Вертикальная доска рисует вертикальные разделительные линии, горизонтальная —
горизонтальные. Оси лаг остаются вертикальными; координаты креплений при смене
ориентации не меняются.

Условное количество полос облицовки по полной стене:

```text
vertical:   ceil(wallWidth_mm / boardWidth_mm)
horizontal: ceil(wallHeight_mm / boardWidth_mm)
```

Это ориентир визуализации, без вычета проёмов, раскроя и запаса. Он не является
точным количеством досок для закупки.

## 7. Итоги

```text
unitCount = points.length
packs = ceil(unitCount / 10)
screws = unitCount × 2
grossArea = wallWidth × wallHeight
netArea = grossArea − sum(opening.w × opening.h)
lagCount = lagPositions.length
spanCount = lagCount − 1
rowCount = rowPositions.length
```

Количество пролётов и рядов показано до исключения проёмов; количество креплений —
после проверки всех пересечений. Даже ряд без допустимых точек остаётся в
общем числе геометрических рядов.

## 9. Экспорт

SVG содержит только облицовку, оси лаг с разрывами, окна/двери, размерные линии
и маркеры. Конструкция изделия не отображается. Предупреждение включено в `desc`.

JSON версии 2 сохраняет параметры, оси, пролёты, ряды, проёмы, точки и результаты.
Неиспользуемые верхнеуровневые `sillHeightMm` и `mullionWidthMm` равны `null`;
состояние формы сохраняет их последние значения для переключения пресетов.
Формат версии 2 заменяет прежнюю модель `battenSpacing` / `density`.
Пути к изображениям и геометрия изделия в JSON не включаются.

## Перед инженерным применением

Необходимо подтвердить допустимые схемы, шаги и отступы, правила обрамления
проёмов и остаточных пролётов, влияние ориентации и параметров доски, основания
и нагрузок. До этого результаты остаются демонстрацией интерфейса.
