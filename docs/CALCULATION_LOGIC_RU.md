# SlidFix calculator — логика прототипа

Это **UX-прототип**, а не финальный инженерный калькулятор.

## Уже зафиксированные продуктовые значения
- 10 SlidFix в одной упаковке.
- 2 шурупа на один SlidFix.
- Пружина: проволока 2 мм, диаметр навивки 11 мм, 28 витков.

## Демонстрационная логика расстановки
Код строит сетку потенциальных точек по ширине и высоте стены:
- горизонтальный шаг = `battenSpacing` пользователя;
- вертикальный шаг Standard = 500 мм;
- вертикальный шаг Dense = 350 мм;
- отступ от наружного края = 180 мм;
- защитная зона вокруг проёма = 110 мм.

Эти четыре инженерных числа являются **placeholder values** и находятся в `app.js`:

```js
const ENGINEERING = {
  packSize: 10,
  screwsPerUnit: 2,
  standardVerticalPitchMm: 500,
  denseVerticalPitchMm: 350,
  edgeClearanceMm: 180,
  openingClearanceMm: 110,
};
```

После появления финального монтажного регламента их можно заменить без переделки UI.

## Presets стены
1. Blank wall — без проёмов.
2. Window center — одно окно по центру.
3. Door left — дверь слева.
4. Door center — дверь по центру.
5. Two windows — два окна.

## Паттерны
### Standard
Прямая ортогональная сетка.

### Staggered
Каждый второй горизонтальный ряд смещён на половину горизонтального шага.

## Вычисления
- `grossArea = wallWidth × wallHeight`
- `netArea = grossArea − area(openings)`
- `unitCount = количество валидных точек сетки вне openings + clear zone`
- `packs = ceil(unitCount / 10)`
- `screws = unitCount × 2`
- `boardCourses = ceil(wallHeight_mm / boardWidth_mm)` — только UI-ориентир.

## Что желательно определить перед production
- Что является реальной осью установки SlidFix: по обрешётке, по стыкам досок или комбинированно.
- Максимальный/рекомендуемый шаг между узлами.
- Отступ от края стены.
- Отступ от окна/двери.
- Нужны ли дополнительные узлы вокруг углов проёмов.
- Зависимость количества от ширины/толщины/породы доски и ветровой нагрузки.
- Разрешены ли разные схемы Standard / Staggered инженерно, либо одна из них только визуальная опция.


## Подготовка статического сайта

Рабочие файлы перенесены в корень: `index.html`, `styles.css`, `app.js`.
Горизонтальный шаг теперь точно соответствует полю Batten spacing (200–1200 мм).
Размеры проёмов ограничиваются геометрией выбранного пресета; поля показывают
эффективные значения. Для Two windows размеры применяются к каждому окну.
При переходе к двери исходная высота — 2,1 м, ограниченная высотой стены;
пользователь может изменить её. Это значение формы, а не монтажная рекомендация.
Нижняя координата двери всегда равна нулю. Ограничения пресетов служат только
для размещения проёмов внутри стены и не заменяют инженерных правил.

Четыре исходных placeholder-значения (500, 350, 180 и 110 мм) сохранены.
Демонстрационное предупреждение присутствует в интерфейсе и обоих экспортах.
Невалидный ввод сохраняет последний корректный расчёт до завершения редактирования;
после ухода из поля число приводится к допустимому диапазону.
